## v0.5 «Запуск и чтение»
- [x] 1. Хвосты репозитория: описание, темы, GitHub Actions (pytest на Python 3.10-3.12), бейдж
- [x] 2. Ресурсы: автоподбор `nprocs` и `maxcore`, проверка `nprocs × maxcore` против ОЗУ в линтере
- [x] 3. Расширенный парсер: геометрия в `.xyz`, HOMO/LUMO, заряды, многошаговые оптимизации, версия ORCA; проверено на реальном `.out` воды (ORCA 6.1.1); сульфоксид проверим в пункте 16
- [x] 4. Экспорт и таблицы: CSV, JSON, Markdown; относительные энергии и ΔG в ккал/моль, распределение Больцмана
- [x] 5. Команда `watch`: энергия, сходимость, время на цикл (оценка остатка не делается: число циклов неизвестно заранее)
- [x] 6. Графики: ход оптимизации, ИК-спектр (профиль скана перенесён в пункт 13: нужен реальный вывод скана)
- [x] 7. Очередь задач: последовательно и (если хватает ядер и памяти) параллельно; возобновление: готовые расчёты пропускаются
- [x] 8. SLURM и PBS Pro: генератор скриптов (Torque не поддерживается; планировщиком не проверялось)

## v0.6 «Починка»
- [x] 9. База правил диагностики: ключевые слова, мультиплетность, SCF, оптимизация, мнимые частоты, оборванный вывод (правило про память только как предположение: реального примера нет)
- [x] 10. Команда `fix`: исправленная копия `.inp` с разницей (SCF, лимит оптимизации, мультиплетность по запросу, подсказки по ключевым словам); мнимые частоты пока не автоматизированы
- [x] 11. Осторожный автоперезапуск (`auto`): только безопасные исправления из `fix`, лимит попыток, остановка при необходимости решения человека, журнал
- [x] 12. (`check` — линтер входов, `doctor` — поиск настоящей ORCA и проверка окружения; различия версий ORCA 5 и 6 переносятся в этап деталей, пункт C) Линтер готовых `.inp`, написанных вручную, с проверкой под ORCA 5 и 6; проверка, что `orca` в PATH — это ORCA, а не экранный диктор GNOME
